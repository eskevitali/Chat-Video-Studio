# Техническая архитектура

## 1. Рекомендуемый стек

- TypeScript — общий язык приложения;
- React — интерфейс редактора и визуальный шаблон чата;
- Electron на MVP — доступ к файлам, системному хранилищу секретов и рендеру;
- Remotion — покадровая композиция, предпросмотр и программный рендер;
- FFmpeg — анализ, нормализация, объединение и финальное кодирование аудио/видео;
- Zod или JSON Schema/Ajv — runtime-валидация проекта;
- SQLite либо JSON-файл — индекс проектов; сам проект остаётся переносимым каталогом.

Electron выбран для первой версии из-за единой Node.js/React-экосистемы. Архитектура
не должна связывать доменную модель с Electron, чтобы позднее можно было заменить
оболочку на Tauri или локальное веб-приложение.

## 3. Границы модулей

### Domain

Чистые типы и правила проекта. Не импортирует React, Electron, FFmpeg или SDK
провайдеров.

### Import

Преобразует Markdown и JSON экспортёров в доменную модель. Не создаёт аудио.

### Speech

Интерфейс провайдера:

```ts
interface SpeechProvider {
  generate(request: SpeechRequest): Promise<GeneratedTake>;
}
```

ElevenLabs реализуется адаптером. В будущем можно добавить другие провайдеры без
изменения редактора и рендера.

### Alignment

Преобразует тайминги провайдера или результат forced alignment в единый формат:

```ts
type WordTiming = {
  text: string;
  startMs: number;
  endMs: number;
};
```

### Timeline Compiler

Получает проект и возвращает неизменяемый `CompiledTimeline`. Он не обращается к
сети и не изменяет проект.

### Renderer

Получает только `CompiledTimeline`, тему и локальные ассеты. Отсутствие сети во
время рендера является обязательным условием воспроизводимости.

## 4. Каталог проекта

```text
my-video.chatvideo/
├── project.json
├── source/
│   └── original.md
├── audio/
│   └── msg-003/
│       ├── take-001.mp3
│       └── take-002.mp3
├── timing/
│   └── msg-003/
│       ├── take-001.json
│       └── take-002.json
├── images/
│   └── avatars/
├── themes/
│   └── custom-theme.json
├── cache/
└── output/
```

Пути в `project.json` должны быть относительными. Проект можно перенести на другой
компьютер целиком. Временные файлы и кадры не должны смешиваться с исходными
ассетами.

## 5. Идентификаторы и версии

- все сущности получают UUID;
- `formatVersion` версионирует JSON-контракт;
- `rendererVersion` фиксируется в метаданных экспорта;
- дубль неизменяем: изменение параметров создаёт новый дубль;
- удаление сообщения не удаляет ассеты автоматически до команды очистки проекта.

## 6. Хеширование и кеш

Ключ TTS-кеша:

```text
SHA-256(provider + model + voice + normalizedText + settings)
```

Перед запросом приложение проверяет локальный кеш и предлагает использовать уже
существующий дубль. Автоматическое повторное списание без явного действия
пользователя запрещено.

Ключ рендер-кеша учитывает тему, разрешение, FPS, шрифт, compiled timeline и хеши
всех ассетов.

## 7. Безопасность

- ElevenLabs API key хранится через системное хранилище секретов;
- ключ не передаётся в renderer-процесс;
- IPC использует разрешённый перечень команд и валидируемые payload;
- remote content и произвольный JavaScript внутри темы запрещены;
- Markdown не может создавать HTML, iframe или сетевые ресурсы;
- импортированные пути нормализуются и не могут выходить за каталог проекта;
- журнал запросов не содержит API-ключ и полный текст по умолчанию;
- перед первым TTS-запросом показывается, какой текст уйдёт провайдеру.

## 8. Работа с аудио

После генерации или импорта приложение:

1. проверяет декодирование;
2. определяет точную длительность через ffprobe;
3. при необходимости преобразует файл в рабочий формат;
4. нормализует громкость без изменения оригинала;
5. валидирует монотонность таймингов;
6. сохраняет waveform cache для таймлайна.

Рабочий формат рекомендуется унифицировать до WAV PCM для монтажа, сохраняя
оригинальный файл. В финальном MP4 используется AAC.

## 9. Сохранение проекта

- изменения сначала записываются во временный файл рядом с `project.json`;
- после успешной сериализации выполняется атомарная замена;
- автосохранение работает после значимых действий с debounce;
- перед миграцией формата создаётся резервная копия;
- проект открывается даже при отсутствии части ассетов, показывая диагностику.

## 10. Интеграция расширений

Экспортёры должны формировать нейтральный `chat-export.json`, а приложение —
преобразовывать его в полный проект. Это не позволит версии desktop-проекта
жёстко зависеть от версии расширения.

Минимальный контракт экспортёра:

```json
{
  "format": "chat-export",
  "version": 1,
  "source": { "platform": "chatgpt", "title": "...", "url": "..." },
  "messages": [
    { "id": "source-1", "role": "user", "text": "..." },
    { "id": "source-2", "role": "assistant", "text": "..." }
  ]
}
```

## 11. Тестирование

### Unit

- Markdown parser;
- миграции JSON;
- группировка символов в слова;
- timeline compiler;
- ripple-пересчёт;
- вычисление прокрутки;
- хеширование кеша.

### Integration

- mock ElevenLabs adapter;
- импорт аудио + ffprobe;
- замена активного дубля;
- сохранение и повторное открытие проекта;
- рендер короткого эталонного проекта.

### Visual regression

Для фиксированных кадров хранятся эталонные изображения тем. Допуск сравнения
задаётся отдельно для текста и геометрии.
