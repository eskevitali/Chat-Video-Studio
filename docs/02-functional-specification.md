# Функциональная спецификация

## 1. Сущности

### Project

Содержит метаданные, участников, сообщения, тему, настройки таймлайна и экспорта.

### Participant

Участник диалога: имя, роль, аватар, визуальный стиль и настройка голоса.

### Message

Одна визуальная реплика чата. Может состоять из нескольких аудиосегментов, но
в интерфейсе отображается одним пузырём.

### Segment

Минимальная единица генерации и замены аудио. Короткая реплика обычно содержит
один сегмент; длинная может быть разделена по предложениям.

### AudioTake

Неизменяемый результат одной генерации или одного импорта. Сегмент ссылается на
активный дубль через `activeTakeId`.

### Theme

Набор токенов оформления браузера и чата. Не содержит сценарий или тайминги.

## 2. Импорт

### 2.1. Markdown

Поддерживаемая структура:

```md
# Название

## Пользователь

Текст реплики.

---

## ChatGPT

Текст ответа.
```

Правила:

- заголовок первого уровня становится названием проекта;
- заголовки второго уровня определяют участника;
- `---` разделяет реплики, но не является обязательным при наличии заголовков;
- неизвестное имя создаёт нового участника;
- пустые реплики игнорируются;
- исходный Markdown сохраняется в метаданных импорта;
- перед созданием проекта показывается экран проверки распознавания.

### 2.2. JSON

JSON должен пройти валидацию по `schemas/project.schema.json`. При несовпадении
версии приложение выполняет миграцию либо сообщает понятную ошибку.

### 2.3. Экспортёры браузера

Расширения ChatGPT и Gemini в следующей версии должны получить дополнительную
команду `Экспортировать проект JSON`. Экспорт не должен включать API-ключи,
cookie, токены авторизации или внутренние сетевые адреса аудиопотоков.

## 3. Редактор сценария

Пользователь может:

- редактировать текст сообщения;
- менять участника;
- добавлять, удалять и переставлять сообщения;
- делить сообщение на аудиосегменты;
- объединять соседние сегменты одного сообщения;
- задавать паузу до и после сообщения;
- отключать сообщение без удаления;
- помечать сообщение как готовое или требующее озвучки.

Изменение текста сегмента делает его активный дубль устаревшим. Дубль остаётся
доступным, но приложение показывает предупреждение о несовпадении текста.

## 4. Голоса и аудио

Для участника задаётся голос по умолчанию. Сегмент может переопределить его.
Два основных участника могут использовать разные `voiceId`; изменение голоса
одного участника не затрагивает дубли другого.

Поддерживаемые источники MVP:

- `elevenlabs` — генерация через API;
- `imported` — локальный MP3/WAV/M4A;
- `recorded` — резерв для будущей записи микрофона;
- `silent` — реплика без озвучки.

### 4.1. Генерация ElevenLabs

Перед запросом показываются текст, голос и параметры. API-ключ хранится в
системном хранилище секретов и никогда не записывается в проект.

Результат запроса сохраняется немедленно, даже если пользователь затем выберет
другой дубль. Для каждого дубля фиксируются:

- идентификатор;
- провайдер и модель;
- voice ID;
- параметры генерации;
- хеш исходного текста;
- локальный путь к аудио;
- длительность;
- тайминги символов или слов;
- дата создания;
- статус и сообщение ошибки.

### 4.2. Ручной импорт

После выбора файла приложение копирует его в каталог проекта и создаёт дубль.
Если таймингов нет, сегмент получает статус `alignment_required`.

### 4.3. Перегенерация

Команда доступна для выбранного сегмента. Она создаёт новый `AudioTake`, делает
его активным после успешной генерации и запускает пересчёт таймлайна.

При ошибке активный дубль не изменяется.

### 4.4. История дублей

Пользователь может прослушать, переименовать, активировать и удалить неактивный
дубль. Активный дубль нельзя удалить без выбора замены или подтверждения перехода
сегмента в состояние без аудио.

## 5. Синхронизация текста

Режимы раскрытия:

- `word` — режим MVP и значение по умолчанию;
- `character` — точное посимвольное раскрытие;
- `sentence` — будущее расширение;
- `instant` — показать сообщение сразу.

Если провайдер вернул посимвольные тайминги, приложение группирует их в слова.
Пробел и знак пунктуации присоединяются к предыдущему слову. Во время паузы в
аудио текст не изменяется.

При отсутствии alignment доступен приблизительный режим, но экспорт показывает
предупреждение. Приблизительные тайминги вычисляются пропорционально длине слов
с минимальной длительностью слова 80 мс.

## 6. Темы и симулятор браузера

Приложение содержит как минимум три темы MVP:

- `minimal-light`;
- `minimal-dark`;
- `ai-chat-inspired`.

Темы могут быть вдохновлены известными чатами, но не должны копировать закрытый
CSS, выдавать приложение за официальный продукт или требовать DOM исходного сайта.

Редактируемые параметры:

- фон сцены и браузера;
- размеры и скругление окна;
- наличие панели браузера и адресной строки;
- заголовок вкладки и демонстрационный URL;
- шрифт, размер, высота строки и ширина контента;
- цвета сообщений и текста;
- расположение, размер и форма аватаров;
- отступы, максимальная ширина пузыря и радиус;
- вид индикатора набора;
- скорость и плавность прокрутки.

Пользователь может сохранить изменённую тему как новый пресет.

## 7. Предпросмотр

Предпросмотр должен поддерживать:

- воспроизведение и паузу;
- перемотку по общей шкале;
- переход к выбранному сообщению;
- обновление после смены дубля без полного видеорендера;
- отображение безопасных зон вертикальных платформ;
- масштабирование сцены без изменения результата экспорта.

При выборе визуального клипа автоматически выбирается соответствующее сообщение
и аудиосегмент. При выборе сообщения таймлайн перемещается к его началу.

## 8. Экспорт

MVP экспортирует:

- MP4, H.264, AAC;
- 1080×1920, 30 FPS;
- необязательный SRT;
- необязательный WAV или M4A с итоговым миксом.

Экспорт блокируется, если отсутствует обязательный аудиофайл. Несовпадение текста
и активного дубля требует подтверждения. Проект без alignment экспортируется с
предупреждением.

## 9. Состояния сегмента

```text
draft
  ↓
needs_audio
  ↓
generating ──ошибка──> generation_failed
  ↓
needs_alignment
  ↓
ready

ready ──изменение текста──> stale_audio
stale_audio ──новый дубль──> ready
```

## 10. Ошибки

Пользователь должен получать отдельные сообщения для:

- неверного API-ключа;
- отсутствия доступа к голосу или модели;
- превышения квоты;
- сетевой ошибки;
- повреждённого аудиофайла;
- несовпадения alignment и текста;
- отсутствующего локального ассета;
- ошибки видеорендера.

Ошибка одной реплики не должна повреждать проект или удалять существующий дубль.
