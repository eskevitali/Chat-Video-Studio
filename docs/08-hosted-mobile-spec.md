# ТЗ и спецификация: веб/мобильный VChat

Дата: 2026-09-05  
Домен: `https://vchat.lokvita.org`  
Хост: KIDer, отдельный Docker Compose, вход через Nginx Proxy Manager.

Документ задаёт **хостовую редакцию** Chat Video Studio. Локальный прототип (`docs/01`…`07`) остаётся источником доменной модели. Здесь — отличия, которые нужно реализовать и принять.

## 1. Назначение

Тот же продукт: Markdown/JSON-диалог → озвучка → таймлайн → MP4 в окне виртуального чата. Оболочка меняется: не Vite на `127.0.0.1`, а браузерное приложение (телефон и десктоп) за HTTPS.

Аудитория не меняется: Shorts / TikTok / Reels, разборы диалогов с ИИ. Первый оператор — владелец кабинета; URL не рекламируется с lokvita.org.

## 2. Цели этой итерации

1. Сохранить рабочий функционал прототипа (импорт, редактор, дубли, темы, кадр, превью, экспорт MP4).
2. Убрать локальную озвучку XTTS / Whisper. Единственный TTS — ElevenLabs.
3. Ключ API и Voice ID вводятся в настройках приложения, а не в `.env.local`.
4. Интерфейс пригоден для телефона: те же действия, крупные зоны нажатия, без обязательного drag-and-drop.
5. Собрать Docker-образ и выдать его на KIDer как `vchat.lokvita.org`.

Не цели: Electron, аккаунты/оплаты, облачная очередь рендера, SRT, расширения ChatGPT/Gemini, автопостинг, совместное редактирование.

## 3. Принципы (наследуют `docs/01`)

- Недеструктивные дубли: новая генерация создаёт take, старый не стирается.
- Ripple: смена активного дубля сдвигает последующие клипы.
- Тема не трогает аудио.
- Ключ ElevenLabs не попадает в `project.json`, JSON-снимок, логи и Git.
- Детерминированный рендер: без сети во время Remotion.

## 4. Функциональная спецификация (дельты)

### 4.1. Настройки приложения

Отдельное хранилище браузера `chat-video-studio.app-settings.v1` (не снимок проекта):

| Поле | Правила |
|---|---|
| `apiKey` | строка до 256 символов; поле типа password; показ/скрытие |
| `userVoiceId` | `^[A-Za-z0-9_-]{1,100}$` |
| `assistantVoiceId` | то же |

Пустые настройки не блокируют просмотр демо, но блокируют «Озвучить» с понятной ошибкой и переходом в настройки.

Голоса из настроек записываются в `project.elevenLabs` (чтобы снимок проекта помнил, какими голосами озвучивали). Ключ — только в настройках.

`.env.local` остаётся запасным путём **только для локального `pnpm dev`**. В Docker-образ ключ не кладётся.

### 4.2. Озвучка

- Провайдер новых дублей всегда `elevenlabs`.
- Модели: Multilingual v2, Flash v2.5, Turbo v2.5 (как сейчас).
- Перед запросом — подтверждение с оценкой кредитов (1 символ ≈ 1 кредит).
- Тело `/api/tts` содержит `apiKey`, `userVoiceId` / `assistantVoiceId`, `modelId`, `text`, `role`, `messageId`.
- Сервер проксирует ElevenLabs `with-timestamps`, пишет MP3 в `public/generated/<messageId>/`, возвращает take с `alignment: provider`.
- Очередь по-прежнему последовательная (одна активная задача).
- XTTS в UI отсутствует. Старые снимки с `ttsProvider: "xtts"` открываются; новый дубль идёт в ElevenLabs.

### 4.3. Редактор (без регрессий)

Сохранить:

- импорт `.md` / `.json`, экспорт JSON-снимка, автосохранение проекта;
- правка текста и подписи роли, порядок (кнопки и drag-and-drop на десктопе);
- удаление реплики (минимум одна остаётся);
- история дублей, прослушивание, активация;
- изображения PNG/JPEG/WebP;
- темы neutral / ChatGPT / Gemini, цвета, заголовок, подпись;
- кадр 9:16, 16:9, 1:1, масштаб UI, скорость набора, FPS;
- превью Remotion Player, переход с клипа в плеер;
- экспорт MP4 (H.264/AAC), скачивание.

На телефоне drag-and-drop не обязателен: порядок меняется кнопками «Раньше» / «Позже».

### 4.4. Мобильный интерфейс

Ширина < 860px:

| Вкладка | Содержимое |
|---|---|
| Сценарий | выбранная реплика, текст, дубль, картинки |
| Превью | плеер на всю ширину, сохраняет aspect-ratio кадра |
| Таймлайн | шкала, волна, сравнение дублей |
| Настройки | API-ключ, Voice ID, модель, оформление, кадр |

Нижняя панель вкладок с учётом `safe-area-inset-bottom`. Кнопки ≥ 44px. `body` без `min-width: 960px`.

Ширина ≥ 860px: прежняя двухколоночная раскладка (сценарий слева, превью+таймлайн справа). Блок «Настройки» — первым в левой колонке.

### 4.5. Ошибки (добавления к `docs/02` §10)

Отдельные сообщения:

- нет API-ключа;
- нет Voice ID для роли;
- ElevenLabs отклонил ключ / голос / квоту;
- очередь TTS переполнена;
- рендер уже идёт;
- Chrome/Chromium недоступен в контейнере.

## 5. Техническая архитектура

```text
телефон/десктоп  HTTPS  vchat.lokvita.org
        │
        ▼
 Nginx Proxy Manager  (сеть nginx_default, TLS Let's Encrypt)
        │
        ▼
 контейнер vchat: Node 20
   ┌─ static: Vite dist + public/{audio,generated,uploads,renders}
   ├─ POST /api/tts      → ElevenLabs, ключ из тела запроса
   ├─ POST /api/image
   ├─ POST /api/render   → Remotion CLI + Chromium
   ├─ GET  /api/render/:id
   └─ GET  /api/health
```

Доменная модель, timeline compiler и шаблон чата не меняют контракт. Меняется оболочка: `server/index.mjs` вместо «только Vite middleware».

Локальная разработка: `pnpm dev` по-прежнему поднимает те же `/api/*` через Vite-плагин, который вызывает общий `server/api.mjs`.

### 5.1. Безопасность

- Ключ не логировать, не писать на диск сервера, не класть в JSON проекта.
- CORS: только `PUBLIC_ORIGIN` и loopback `:4173`.
- Voice ID и messageId санитизируются (как сейчас).
- Пути ассетов не выходят из каталогов generated/uploads/renders.
- GitHub-репозиторий публичный: в образ не попадают `.env`, дубли, загрузки.
- Авторизации нет (осознанно, итерация 1). Риск: любой, кто знает URL, может грузить картинки и запускать рендер на CPU/RAM KIDer. Смягчение: URL не связан с главной lokvita.org; один рендер одновременно; лимит 500 реплик. Базовый auth — следующая итерация, если понадобится.

### 5.2. Данные

| Что | Где |
|---|---|
| Проект, настройки, ключ | `localStorage` браузера оператора |
| MP3 дублей, картинки, MP4 | тома Docker `public/generated|uploads|renders` |
| Демо-аудио | `public/audio/elevenlabs-*.mp3` в Git (короткие файлы) |

Перенос телефона → десктоп: JSON-снимок (аудио в снимок не входит; на другом устройстве дубли нужно генерировать заново либо это тот же браузерный профиль).

### 5.3. Контейнер

- Образ: Node 22 + Chromium + шрифты Noto/Liberation (pnpm 11 нужен `node:sqlite`).
- `CHROME_NO_SANDBOX=1`, `shm_size: 2g`, `concurrency=1`.
- Сеть: `nginx_default` (DNS-имя контейнера `vchat`, порт 4173).
- Ресурсы: лимит памяти 6g, чтобы не вытеснить lokvita / kiderstudio.
- Healthcheck: `GET /api/health`.

## 8. Ключевые решения

1. **Веб, не Electron** — телефон не ставит десктоп; KIDer уже раздаёт HTTPS через NPM.
2. **Ключ в браузере, сервер — прокси** — публичный GitHub и общий контейнер не должны хранить секрет; каждый оператор несёт свой ключ.
3. **Без XTTS на хосте** — на KIDer нет GPU под Coqui; пользователь явно отказался от локальной озвучки.
4. **Один контейнер** — SPA + API + Remotion. Отдельный render-worker не окупается на одном операторе.
5. **Вкладки на мобиле, не сжатие десктопа** — таймлайн и плеер не живут в 360px одновременно без потери эргономики.
