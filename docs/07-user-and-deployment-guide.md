# Chat Video Studio: руководство пользователя и развёртывание

## 1. Назначение

Chat Video Studio — локальное веб-приложение для создания MP4-видео из текстового
диалога. Приложение показывает реплики в стилизованном окне чата, синхронно
раскрывает текст, воспроизводит озвучку, вставляет изображения и автоматически
прокручивает чат вслед за активной репликой.

Основной рабочий процесс:

1. Импортировать диалог из Markdown или ранее сохранённого JSON.
2. Отредактировать текст, имена участников и порядок реплик.
3. Настроить оформление и формат видеокадра.
4. Создать озвучку через ElevenLabs или локальный XTTS v2.
5. Выбрать активные дубли и при необходимости добавить изображения.
6. Проверить результат в видеоплеере.
7. Экспортировать MP4.

Хостовая редакция (телефон + десктоп, только ElevenLabs, Docker на KIDer):
см. `docs/08-hosted-mobile-spec.md` и `docs/09-kider-deployment.md`.
Ниже — исходное руководство локального прототипа.

Приложение в локальном режиме рассчитано на запуск на одном доверенном компьютере.

## 2. Возможности

- Импорт Markdown-диалогов и JSON-снимков проекта.
- Автосохранение проекта в `localStorage` браузера.
- Ручное сохранение и восстановление JSON-снимка.
- Редактирование текста и подписей ролей.
- Перетаскивание реплик на таймлайне и перемещение кнопками.
- Удаление реплик с подтверждением.
- Масштабирование и независимая горизонтальная прокрутка таймлайна.
- Цветовые состояния клипов: готовое аудио, отсутствие аудио, генерация.
- История нескольких аудиодублей и явный выбор активного дубля.
- Последовательная очередь TTS: одновременно выполняется только одна задача.
- ElevenLabs Multilingual v2, Flash v2.5 и Turbo v2.5.
- Отдельные Voice ID пользователя и ассистента.
- Локальная генерация XTTS v2 и выравнивание слов через faster-whisper.
- Вложения PNG, JPEG и WebP внутри реплик.
- Вертикальный 9:16, горизонтальный 16:9 и квадратный 1:1 форматы.
- Локальный MP4-рендер через Remotion.

## 3. Системные требования

### Обязательно

- Linux. Текущая команда экспорта ожидает Google Chrome по пути
  `/usr/bin/google-chrome`.
- Node.js 20 или новее.
- pnpm 11 или совместимая версия.
- Google Chrome для Remotion-рендера.
- Достаточно свободного места для `node_modules`, аудио, изображений и MP4.

### Для ElevenLabs

- Интернет-соединение.
- Аккаунт и API-ключ ElevenLabs.
- Voice ID для обеих ролей либо значения, введённые в интерфейсе.

### Для XTTS v2

- Python 3.12.
- Отдельное виртуальное окружение `.venv-xtts`.
- Рекомендуется NVIDIA GPU с совместимым CUDA-окружением.
- XTTS может работать на CPU, но генерация и Whisper будут значительно медленнее.
- Чистые голосовые образцы WAV длительностью примерно 10–30 секунд.

Проверенное локальное окружение использует PyTorch 2.6.0, CUDA 12.4,
`coqui-tts==0.27.5`, `transformers==4.57.6` и
`faster-whisper==1.2.1`.

## 4. Быстрое локальное развёртывание

Перейдите в каталог проекта:

```bash
cd /путь/к/chat-video-studio
```

Установите зависимости:

```bash
pnpm install
```

Создайте локальную конфигурацию:

```bash
cp .env.example .env.local
```

Заполните `.env.local`, затем выполните проверку:

```bash
pnpm test
pnpm build
```

Запустите приложение:

```bash
pnpm dev
```

Откройте:

```text
http://127.0.0.1:4173/
```

Сервер намеренно слушает только `127.0.0.1`. Это защищает локальные API и ключ
ElevenLabs от доступа из локальной сети.

### Локальный вспомогательный запуск

В текущем рабочем окружении присутствует `run-dev.sh`:

```bash
bash run-dev.sh
```

Скрипт содержит абсолютный путь к Node.js конкретной машины. Для переносимого
развёртывания используйте `pnpm dev` или исправьте `NODE_BIN` в `run-dev.sh`.

## 5. Конфигурация `.env.local`

Пример:

```dotenv
ELEVENLABS_API_KEY=ваш_секретный_ключ
ELEVENLABS_USER_VOICE_ID=id_голоса_пользователя
ELEVENLABS_ASSISTANT_VOICE_ID=id_голоса_ассистента
ELEVENLABS_MODEL_ID=eleven_multilingual_v2

XTTS_USER_REFERENCE=/абсолютный/путь/user.wav
XTTS_ASSISTANT_REFERENCE=/абсолютный/путь/assistant.wav
XTTS_LANGUAGE=ru
XTTS_ALIGNMENT_MODEL=small
```

### Переменные ElevenLabs

| Переменная | Назначение | Обязательность |
|---|---|---|
| `ELEVENLABS_API_KEY` | Секретный API-ключ | Обязательна для ElevenLabs |
| `ELEVENLABS_USER_VOICE_ID` | Голос роли `user` | Нужна, если поле в интерфейсе пустое |
| `ELEVENLABS_ASSISTANT_VOICE_ID` | Голос роли `assistant` | Нужна, если поле в интерфейсе пустое |
| `ELEVENLABS_MODEL_ID` | Модель по умолчанию | Необязательна |
| `ELEVENLABS_VOICE_ID` | Старое имя голоса пользователя | Только для обратной совместимости |

Поддерживаемые модели:

- `eleven_multilingual_v2` — стабильное качество для длинного многоязычного текста;
- `eleven_flash_v2_5` — более быстрая и экономичная модель;
- `eleven_turbo_v2_5` — сохранена для совместимости, но Flash предпочтительнее.

Выбор в блоке «Озвучка» имеет приоритет над `ELEVENLABS_MODEL_ID`. Введённые в
интерфейсе Voice ID имеют приоритет над `.env.local`.

### Переменные XTTS

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `XTTS_USER_REFERENCE` | `voice-samples/user.wav` | Образец пользователя |
| `XTTS_ASSISTANT_REFERENCE` | `voice-samples/assistant.wav` | Образец ассистента |
| `XTTS_LANGUAGE` | `ru` | Язык синтеза и распознавания |
| `XTTS_ALIGNMENT_MODEL` | `small` | Модель faster-whisper |

Никогда не добавляйте `.env.local` в Git и не отправляйте его другим людям.

## 6. Установка XTTS v2

Создайте окружение Python 3.12:

```bash
python3.12 -m venv .venv-xtts
```

Установите PyTorch для подходящей платформы. Пример проверенной CUDA 12.4
конфигурации:

```bash
.venv-xtts/bin/python -m pip install --upgrade pip
.venv-xtts/bin/python -m pip install torch==2.6.0 torchaudio==2.6.0 --index-url https://download.pytorch.org/whl/cu124
.venv-xtts/bin/python -m pip install -r requirements-xtts.txt
```

Положите образцы в:

```text
voice-samples/user.wav
voice-samples/assistant.wav
```

Либо укажите абсолютные пути в `.env.local`.

Загрузите модель и лично подтвердите лицензионные условия CPML:

```bash
pnpm xtts:setup
```

После установки перезапустите сервер и выберите «XTTS v2 · локально».

Важно: лицензия и допустимые способы использования XTTS должны быть проверены
владельцем развёртывания до коммерческого применения.

## 7. Интерфейс

### Верхняя панель

- «Вернуть демо» заменяет текущий проект демонстрационным.
- «Сохранить .json» скачивает снимок проекта.
- «Импортировать» принимает Markdown или JSON.
- «Экспорт MP4» запускает локальный Remotion-рендер.
- «Скачать MP4» появляется после успешного рендера.

### Оформление

Сворачиваемый блок содержит:

- визуальный пресет;
- заголовок и подпись чата;
- основной фон кадра;
- подложку чата;
- акцент;
- цвета пузырей пользователя и ассистента.

Изменения сразу видны в предпросмотре и сохраняются автоматически.

### Видеокадр

- формат 9:16, 16:9 или 1:1;
- масштаб интерфейса 70–140%;
- скорость индикатора набора 0.5–2.0×;
- 24, 25, 30, 50 или 60 FPS.

### Озвучка

Выберите ElevenLabs или XTTS. Для ElevenLabs доступны модель и отдельные Voice
ID. Если Voice ID пуст, сервер использует `.env.local`.

### Сценарий

Блок можно растягивать по высоте за правый нижний угол. Он показывает только
выбранную на таймлайне реплику.

Доступные действия:

- редактирование подписи автора для всей роли;
- редактирование текста;
- генерация нового дубля;
- выбор активного дубля;
- перемещение раньше или позже;
- удаление реплики;
- добавление и настройка изображений.

Изменение текста снимает старое аудио с активного состояния, поскольку тайминги
перестают соответствовать тексту. Старый дубль сохраняется в истории и может
быть активирован вручную с предупреждением.

## 8. Импорт диалога

### Markdown

Поддерживается структура:

```markdown
# Название диалога

## Пользователь

Первая реплика.

---

## ChatGPT

Ответ ассистента.
```

Авторы `Пользователь`, `User`, `Human`, `Вы` и `You` распознаются как роль
пользователя. Остальные заголовки считаются ролью ассистента.

После импорта создаются черновые тайминги без аудиофайлов.

### JSON

Приложение принимает собственный формат снимка
`chat-video-editor-snapshot`, версия `1`. JSON содержит настройки, тексты,
тайминги, активные дубли, историю дублей и относительные пути медиа.

Аудио и изображения в JSON не встраиваются.

## 9. Озвучка и очередь

### Генерация

1. Выберите реплику на таймлайне.
2. Откройте «Озвучка» и настройте движок.
3. Нажмите «Озвучить» или «Новый дубль».
4. Для ElevenLabs подтвердите ожидаемый расход символов.
5. Дождитесь статуса готовности.

### Очередь и память

Все TTS-запросы выполняются последовательно. Одновременно работает только одна
задача, поэтому несколько экземпляров XTTS не загружаются в память параллельно.
Максимальный размер очереди — 100 активных и ожидающих заданий.

Красный клип означает генерацию или ожидание очереди, зелёный — готовое аудио,
голубой — отсутствие аудиофайла.

### Дубли

Каждая реплика может содержать несколько дублей. Активный дубль используется в
предпросмотре и MP4. Кнопка «Активировать старый» разрешает выбрать аудио от
предыдущей версии текста, но его слова и тайминги могут не совпасть.

### Синхронизация

ElevenLabs возвращает временные метки символов, которые преобразуются в слова.
XTTS сначала создаёт WAV, затем faster-whisper пытается сопоставить распознанные
слова с исходным текстом. При недостаточной уверенности используются
приблизительные тайминги.

Пузырь появляется за 500 мс до начала аудио, чтобы вход и прокрутка успели стать
видимыми до первого звука.

## 10. Изображения

В выбранной реплике нажмите «Добавить» в разделе «Изображения».

Ограничения:

- PNG, JPEG и WebP;
- максимум 10 МБ на файл;
- размер изображения — не более 20 000 × 20 000 пикселей;
- можно добавить несколько изображений.

Настройки:

- над или под текстом;
- вписать полностью или заполнить с обрезкой;
- появление вместе с пузырём, в начале речи или после текста.

Файлы сохраняются в `public/uploads/<messageId>/`. Команда «Убрать» удаляет
связь из проекта, но не удаляет физический файл.

## 11. Таймлайн

- Нажатие клипа выбирает реплику и переводит предпросмотр к её началу.
- Ручная горизонтальная прокрутка не изменяется при выборе реплики.
- «−» и «+» меняют масштаб от 50 до 400%.
- «Вместить всё» показывает весь проект в ширине панели.
- Клип можно перетащить на позицию другого клипа.
- Для точного перемещения на один шаг используйте «Раньше» и «Позже».

После изменения порядка весь таймлайн пересчитывается последовательно.

## 12. Экспорт MP4

Перед экспортом:

1. Просмотрите видео целиком.
2. Проверьте, что нужные дубли активны.
3. Проверьте доступность файлов из `public/generated` и `public/uploads`.
4. Убедитесь, что Chrome доступен как `/usr/bin/google-chrome`.

Нажмите «Экспорт MP4». Сервер допускает только один одновременный рендер и не
более 500 реплик. Remotion запускается с H.264 и `--concurrency=2`.

Результаты сохраняются в:

```text
public/renders/render-<timestamp>-<id>.mp4
```

Временное описание задания создаётся в `.render-jobs/` и удаляется после
завершения. Перезапуск сервера сбрасывает состояние списка заданий в памяти, но
уже созданный MP4 остаётся в `public/renders/`.

## 13. Хранение данных и резервное копирование

| Данные | Расположение |
|---|---|
| Автосохранение | `localStorage` текущего браузера |
| Ручной снимок | скачанный `.json` |
| ElevenLabs MP3 | `public/generated/<messageId>/` |
| XTTS WAV | `public/generated/<messageId>/` |
| Изображения | `public/uploads/<messageId>/` |
| Готовые MP4 | `public/renders/` |
| Голосовые образцы | `voice-samples/` либо пути из `.env.local` |
| Секреты | `.env.local` |

Для полного резервного копирования сохраните:

1. JSON-снимок проекта.
2. `public/generated/`.
3. `public/uploads/`.
4. Нужные файлы из `public/renders/`.
5. Голосовые образцы.
6. `.env.local` отдельно в защищённом хранилище.

При переносе сохраняйте относительную структуру `public/`, иначе пути из JSON
перестанут разрешаться.

## 14. Проверка и обновление

Перед использованием новой версии:

```bash
pnpm install
pnpm test
pnpm build
```

После изменений в `vite.tts-plugin.mjs` или `.env.local` обязательно
перезапустите сервер. Изменения React/CSS обычно применяются через HMR, но для
контрольной проверки лучше обновить страницу.

## 15. Диагностика

### Порт 4173 занят

Остановите старый процесс или измените порт одновременно в `vite.config.ts` и
проверке разрешённого Origin в `vite.tts-plugin.mjs`.

### «ElevenLabs API key не настроен»

Проверьте `ELEVENLABS_API_KEY` и перезапустите сервер.

### «Голос для роли не настроен»

Введите Voice ID в интерфейсе либо заполните соответствующую переменную
`.env.local`.

### Voice ID содержит недопустимые символы

Допускаются латинские буквы, цифры, `_` и `-`, до 100 символов.

### XTTS не находит образец

Проверьте абсолютный путь или наличие `voice-samples/user.wav` и
`voice-samples/assistant.wav`.

### Сервер потребляет слишком много памяти

TTS уже выполняется последовательно. Убедитесь, что не запущено несколько
экземпляров сервера и что параллельно не работает отдельный XTTS-процесс.

### Whisper использует приблизительные тайминги

Улучшите качество и чистоту голосового образца, проверьте язык, GPU и значение
`XTTS_ALIGNMENT_MODEL`. Сам WAV при ошибке выравнивания не теряется.

### Экспорт не запускается

Проверьте `/usr/bin/google-chrome`, свободное место, наличие всех медиа и вывод
терминала Vite. Одновременно может выполняться только один рендер.

### MP4 использует старые данные

Каждый экспорт получает снимок проекта на момент нажатия кнопки. Завершите
редактирование и запустите новый экспорт; уже созданные MP4 не обновляются.

## 16. Безопасность

- Не публикуйте `.env.local`.
- Не размещайте текущий сервер напрямую в интернете.
- Не меняйте `host: '127.0.0.1'` без отдельной аутентификации и пересмотра CORS.
- Не импортируйте JSON из недоверенного источника без проверки путей медиа.
- Храните голосовые образцы как персональные биометрические данные.
- Регулярно очищайте ненужные MP4, аудио и изображения вручную после резервного
  копирования.

## 17. Ограничения текущего развёртывания

`pnpm build` создаёт клиентскую папку `dist/`, но TTS, загрузка изображений и
рендер реализованы внутри Vite-плагина `configureServer`. Поэтому обычная
публикация `dist/` на статическом хостинге не создаёт полноценное приложение.

Поддерживаемый режим сейчас — локальный Vite server через `pnpm dev`. Для
production-сервера потребуется вынести `/api/tts`, `/api/image` и `/api/render`
в отдельный backend, добавить аутентификацию, постоянное хранилище заданий,
настройку допустимых Origin и управление секретами.

## 18. Полезные команды

```bash
pnpm dev                         # локальный сервер
pnpm test                        # все тесты
pnpm build                       # TypeScript + клиентская сборка
pnpm studio                      # Remotion Studio
pnpm render                      # демонстрационный CLI-рендер

```

## 19. Ярлыки рабочего стола

Управляющий скрипт находится в
`scripts/chat-video-studio-control.sh` и поддерживает команды:

```bash
scripts/chat-video-studio-control.sh start
scripts/chat-video-studio-control.sh stop
scripts/chat-video-studio-control.sh status
```

Команда `start` предотвращает повторный запуск, ожидает готовности сервера и
открывает приложение в браузере. `stop` завершает группу процессов только после
проверки, что PID принадлежит каталогу проекта.

Служебные файлы создаются в `.runtime/`:

- `chat-video-studio.pid` — PID управляемого сервера;
- `chat-video-studio.log` — журнал запуска и ошибок;
- `control.lock` — блокировка одновременных команд.

Исходники ярлыков и иконки находятся в `assets/launcher/`. Если каталог проекта
перемещён, обновите абсолютные пути `Exec` и `Icon` в `.desktop`-файлах.

### Ярлык очистки

`Chat Video Studio — Очистка` запускает графический скрипт
`scripts/chat-video-studio-cleanup.sh`. Перед работой сервер должен быть
остановлен.

Режим «Очистить кэш» перемещает в системную корзину только `dist/`, временные
задания и журнал. MP4, аудио, изображения, `.env.local`, `node_modules` и XTTS
не затрагиваются.

Режим «Архивировать проект» принимает сохранённый JSON, собирает `project.json`
и все указанные в нём локальные аудио/изображения в проверяемый `.tar.gz`. Только
после успешного создания архива скрипт отдельно предлагает переместить связанные
медиа в корзину. Готовые MP4 и файлы других проектов не удаляются.
