# План MVP и критерии приёмки

## 1. Этапы разработки

### Этап 0. Технический прототип

- загрузить фиксированный JSON;
- отобразить два сообщения в виртуальном браузере;
- подключить готовые аудиофайлы;
- раскрыть текст по тестовым таймингам;
- выполнить автоматическую прокрутку;
- экспортировать 10–15 секунд MP4.

Результат: доказана работоспособность рендер-конвейера.

### Этап 1. Домен и импорт

- типы и JSON Schema;
- создание/открытие/сохранение проекта;
- импорт Markdown текущих экспортёров;
- экран проверки распознанных сообщений;
- редактор участников и текста.

### Этап 2. Аудиодубли

- подключение ElevenLabs;
- безопасное хранение API-ключа;
- генерация с таймингами;
- ручной импорт аудио;
- история дублей;
- выбор активного дубля;
- кеширование и обработка ошибок.

### Этап 3. Таймлайн

- compiled timeline;
- waveform;
- выбор сообщения и сегмента;
- ripple editing;
- перегенерация выбранного сегмента;
- синхронное обновление предпросмотра.

### Этап 4. Темы

- симулятор окна браузера;
- три встроенные темы;
- редактор токенов;
- сохранение пользовательского пресета;
- safe zones 9:16.

### Этап 5. Экспорт

- MP4 1080×1920/30;
- итоговый аудиомикс;
- SRT;
- прогресс и отмена;
- диагностика отсутствующих ассетов;
- эталонный end-to-end проект.

### Этап 6. Интеграция расширений

- экспорт нейтрального JSON из ChatGPT-расширения;
- экспорт нейтрального JSON из Gemini-расширения;
- проверка совместимости обеих платформ.

## 2. Сквозные критерии приёмки MVP

### Сценарий A: импорт Markdown

**Дано:** файл с чередующимися заголовками `Пользователь` и `ChatGPT`.

**Когда:** пользователь импортирует файл и подтверждает результат.

**Тогда:** создаётся проект с правильным порядком, текстом и двумя участниками.

### Сценарий B: генерация пользовательской реплики

**Дано:** сегмент без аудио и настроенный ElevenLabs API key.

**Когда:** пользователь выбирает голос и нажимает `Сгенерировать`.

**Тогда:** создаётся дубль, сохраняются аудио и тайминги, сегмент получает статус
`ready`, а запрос не повторяется при открытии проекта.

### Сценарий C: неудачная генерация

**Дано:** сегмент с активным рабочим дублем.

**Когда:** повторная генерация завершается ошибкой.

**Тогда:** рабочий дубль остаётся активным, проект воспроизводится как прежде,
ошибка отображается только для новой задачи.

### Сценарий D: замена дубля

**Дано:** сообщение с двумя успешными дублями разной длительности.

**Когда:** пользователь активирует второй дубль.

**Тогда:** длительность сообщения меняется, последующие клипы сдвигаются без
перекрытия, а текст использует тайминги второго дубля.

### Сценарий E: оформление

**Дано:** полностью озвученный проект.

**Когда:** пользователь переключается со светлой темы на тёмную и меняет размер
шрифта.

**Тогда:** аудио и тайминги не меняются, TTS-запросы не выполняются, геометрия и
прокрутка пересчитываются.

### Сценарий F: экспорт

**Дано:** готовый проект длительностью не менее 60 секунд.

**Когда:** пользователь экспортирует MP4.

**Тогда:** файл воспроизводится, содержит все реплики и звук, имеет разрешение
1080×1920, 30 FPS и корректную общую длительность.

## 3. Definition of Done для функции

- реализованы happy path и явно перечисленные ошибки;
- доменная логика покрыта unit-тестами;
- пользовательские данные не теряются при ошибке;
- операция отменяется либо безопасно завершается при закрытии окна;
- UI имеет состояние загрузки, успеха и ошибки;
- данные проходят runtime-валидацию;
- функция проверена на Windows, macOS и Linux либо ограничение задокументировано;
- изменение отражено в документации формата при необходимости.

## 4. Решения, которые нужно принять до реализации

1. Рабочее название и брендинг приложения.
2. Первая целевая ОС: Windows, macOS или Linux.
3. Тип подписки ElevenLabs и доступные модели/лимиты API.
4. Нужен ли forced alignment в MVP или только TTS с готовыми таймингами.
5. Должны ли ответы ИИ по умолчанию быть озвучены вторым голосом ElevenLabs.
6. Требуется ли фоновая музыка в первом релизе.
7. Нужно ли поддерживать горизонтальное видео уже в MVP.
8. Лицензионная модель Remotion для предполагаемого способа использования.

## 5. Следующий практический шаг

Начать с Этапа 0: создать короткий эталонный JSON, два локальных аудиофайла и
одну вертикальную композицию. Прототип должен проверить самое рискованное место —
одновременную синхронизацию раскрытия текста, высоты пузыря и плавной прокрутки.
