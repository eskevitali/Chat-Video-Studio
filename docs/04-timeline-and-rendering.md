# Таймлайн и рендеринг

## 1. Единицы времени

В проекте и compiled timeline время хранится целыми миллисекундами. Перевод в
кадры выполняется только на границе рендера:

```text
frame = round(milliseconds × fps / 1000)
```

Накопление длительностей выполняется в миллисекундах, а не кадрах, чтобы смена
FPS не изменяла логическую длительность проекта.

## 2. Фазы сообщения

Каждое включённое сообщение имеет последовательные фазы:

1. `prePause` — пауза перед активностью;
2. `typingIndicator` — индикатор набора;
3. `bubbleEnter` — появление пузыря;
4. `speech` — аудио и раскрытие текста;
5. `hold` — показ завершённого сообщения;
6. `postPause` — пауза перед следующей репликой.

Для MVP фазы сообщений не пересекаются.

## 3. Компиляция

```ts
type CompiledMessage = {
  messageId: string;
  participantId: string;
  startMs: number;
  typingStartMs: number;
  bubbleStartMs: number;
  speechStartMs: number;
  speechEndMs: number;
  endMs: number;
  words: Array<{
    text: string;
    visibleFromMs: number;
    visibleUntilMs: number;
  }>;
  audioPath?: string;
};
```

Алгоритм идёт по сообщениям слева направо. Начало следующего сообщения зависит от
`endMs` предыдущего. Поэтому изменение длительности одного дубля автоматически
сдвигает все последующие события — ripple editing.

## 4. Замена дубля

При нажатии `Перегенерировать`:

1. создаётся фоновая задача;
2. текущий дубль продолжает использоваться в проекте;
3. новый звук и тайминги проходят валидацию;
4. успешный дубль добавляется в историю;
5. пользователь может прослушать его до применения;
6. команда `Использовать дубль` меняет `activeTakeId`;
7. timeline compiler пересчитывает проект от изменённого сегмента;
8. playhead сохраняет логическую позицию внутри выбранного сообщения.

Опция `Автоматически использовать успешную перегенерацию` может появиться после
MVP, но по умолчанию должна быть выключена.

## 5. Сегменты внутри сообщения

Несколько сегментов визуально составляют один пузырь. Между сегментами может быть
пауза, но `bubbleEnter` выполняется только один раз. Текст каждого сегмента
раскрывается по его активному дублю.

Изменение одного сегмента не требует повторной генерации соседних.

## 6. Раскрытие текста

В режиме `word` слово становится видимым в `startMs` соответствующего тайминга.
Markdown сначала разбирается в безопасное дерево, а раскрытие применяется к
текстовым узлам. Частично открытые Markdown-маркеры в кадр не попадают.

Для MVP поддерживаются:

- абзацы;
- переносы строк;
- жирное и курсивное выделение;
- простые маркированные и нумерованные списки;
- inline code и блоки кода;
- ссылки как оформленный текст без перехода.

Формулы и таблицы импортируются как простой текст либо требуют предварительного
редактирования исходника.

## 7. Геометрия и прокрутка

Рендер сначала вычисляет высоту всех пузырей в завершённом состоянии. Для
активного сообщения также определяется текущая высота на конкретном кадре.

Целевая позиция прокрутки:

```text
targetScroll = max(0, activeBubbleBottom - viewportHeight × anchorRatio)
```

Значение `anchorRatio` по умолчанию — `0.78`.

Фактическая позиция интерполируется к целевой с easing. Для предотвращения дрожи:

- прокрутка не меняется при смещении менее 2 px;
- движение имеет минимальную длительность 180 мс;
- после окончания сообщения допускается доводка до финальной позиции;
- камера никогда не прокручивается вверх автоматически в пределах одной сцены.

## 8. Браузерная сцена

Сцена состоит из слоёв:

```text
background
  browser-shadow
    browser-frame
      browser-toolbar
      chat-header
      scroll-viewport
        messages
      overlays
```

Панель браузера может быть отключена. URL является демонстрационным текстом и не
открывает внешние страницы.

## 9. Аудиомикс

- каждый активный дубль размещается в `speechStartMs`;
- клипы не перекрываются в MVP;
- громкость нормализуется к единой целевой воспринимаемой громкости;
- между клипами не добавляется crossfade, способный обрезать согласные;
- фоновая музыка опциональна и автоматически приглушается во время речи;
- мастер-лимитер предотвращает клиппинг.

## 10. Инкрементальное обновление

Предпросмотр не создаёт MP4 после каждого изменения. React-композиция получает
обновлённый compiled timeline и переиспользует неизменившиеся аудио и layout-кеши.

Финальный рендер всегда выполняется целиком. Оптимизация частичного финального
рендера не входит в MVP, поскольку усложняет переходы, аудиомикс и контроль
целостности.

## 11. Субтитры

SRT строится из тех же word timings, что и раскрытие текста. Реплика делится на
фразы с ограничением длины строки и длительности блока. Субтитры не влияют на
визуальный текст внутри чата.
